## TL;DR

- HTTP API is the "wire you connect yourself" for any tool Clay doesn't natively integrate — endpoint, method, headers, JSON body, field path, auth — distinct from a webhook (fires immediately on a post, before the HTTP API call processes data).
- Web scraping in Clay is a five-rung cost/power ladder: Native Scraper → Chrome Extension → Claygent → Apify → Zenrows. Always try the cheapest plausible tool first; escalate only when blocked.
- Claygent is disproportionately expensive for pure scraping (~$200/1,000 rows) vs. dedicated tools like Apify (~$19/month) — reserve Claygent for reasoning/interpretation, not bulk extraction.
- Clay table hygiene: minimal enrichments, clean names, fewer columns (not one per detail), and output must end in outreach-ready messaging, never just an email/LinkedIn URL.
- Signal filtering discipline: at least 70% of sourced companies should survive qualification. Sampath's table dropped 60 to 6 — "wrong math," a sign of double-filtering or too-narrow a TAM.

## Key concepts

- **HTTP API column** — Clay's general-purpose connector to any API without a native integration; bidirectional (Source to pull in a fresh list, Enrichment to add data to existing rows).
- **Webhook vs. HTTP API** — a webhook fires immediately on a post (e.g. a LinkedIn URL dropped in Slack); the HTTP API request is the GET/POST that actually processes/fetches data once triggered (00:20:58).
- **API vocabulary**: endpoint, method (GET/POST/PUT/DELETE), headers, query parameters, JSON body, field path (dot-path to the exact response value), authentication (API key/bearer token), test vs. production URL (00:12:39, 00:13:45).
- **HTTP error codes** — 400 malformed request, 401 unauthenticated, 403 authenticated but not permitted, 404 endpoint doesn't exist, 429 rate limit exceeded (00:21:58).
- **Scraping's four-step loop** (per instructor doc): request the page, parse HTML, extract values, structure into rows — extraction is the hard part, not the request.
- **Scrape only for gaps** — check first whether a reliable Clay/Apollo/Crunchbase-type source already covers the data point.
- **Signal strictness** — a filter pass dropping the pool below ~50–60% means signals are too strict or qualification is being duplicated across tools (e.g. Prospio then Clay again).
- **Clay execution logic** — a document generated by pasting a written outbound strategy into Claude/GPT and asking it to map what runs in Clay vs. an upstream sourcing tool, to avoid double-filtering.

## Clay build steps demonstrated

1. **Pick HTTP API mode:** existing rows → Enrichment; no table yet → Source.
2. **Read the target API's docs first:** endpoint URL, method, auth method, required parameters/body fields.
3. **Add the column via Sculptor's Generate tab** — describe the request in plain English, let it draft the config.
4. **Inspect the Configure tab** to see the actual method/endpoint/params/field path it built.
5. **Rebuild manually** as a comprehension check: Method, Endpoint URL, Query parameters mapped to table columns, Field path to the one value needed.
6. **Test on one row before running the full table** — universal rule for both HTTP API and scraping.
7. **JSON body rules:** strings need quotes (`"name": "Sam"`); numbers/booleans don't (`"age": 30`); a dynamic string reference needs quotes (`"email": "/Email Column"`); a dynamic number reference doesn't (`"count": /Score Column`); commas between every pair.
8. **Diagnose by status code:** 400 → JSON body; 401 → API key/token; 403 → permissions/scopes; 404 → endpoint URL; 429 → rate limit.
9. **Scraping tool selection order:** visible list/table → Chrome Extension; static page, one field → Native Scraper; unstructured/needs interpretation → Claygent; known platform with a marketplace actor → Apify; site blocking you → Zenrows.
10. **Company table cleanup (Gagan's table):** add a qualifying signal (he used SOC2 compliance), hide low-value columns, confirm the surviving TAM is real.
11. **People-table lookup for messaging:** add a Lookup (single record) enrichment mapped on Company Name against the Company table, to pull company-level messaging into People rows lacking a personal summary (01:13:50).
12. **Credits/rate limits:** no run-condition formula or credit cap was configured on screen this session; the cost framing throughout was default-cheap-first (Native Scraper/Chrome Extension), Claygent only for reasoning, Apify/Zenrows as paid escalation with their own external billing.

## Instructor rules, opinions & decisions

- A table is only a means to execute strategy — keep it clean and always end in outreach-ready messaging, never stopping at an email or LinkedIn URL (00:08:17–00:09:17).
- Fewer columns beat one column per micro-detail; column sprawl breaks scalability (01:12:16, direct feedback to Gagan).
- A clean table should take 2-3 hours to build, not days — slow execution is a business risk, since clients won't keep paying $2-3k/month for slow delivery (00:50:17–00:51:25).
- At least 70% of sourced companies must survive qualification filtering; dropping from 60 to 6 is "wrong math" — too-strict signals, too-narrow TAM, or duplicated filtering (00:52:28–00:55:38).
- Filter companies before people, and don't re-run in Clay a qualification step already done upstream (e.g. in Prospio) (00:55:38–00:59:24).
- Use Claude/GPT to turn a strategy doc into a Clay execution logic doc separating Clay's job from an upstream tool's job (00:58:08).
- Content crawling (systematically scraping a site's ongoing content for resale) sits in a legal gray area — called "not legal" at scale but treated as fine for small, single-use cases; European/American sites are more likely to block it (00:31:12–00:32:02).
- Scraping fills gaps, it isn't a default habit — check existing providers first.
- Time management is a core GTM engineering competency, protecting both margin and the client relationship (00:50:17–00:51:25).
- Tool fluency is a career differentiator — open and understand tools from the shared directory rather than fixating on one (00:44:48–00:49:09).
